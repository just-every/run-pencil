# Release notes

## 0.2.0

**Results and email.** Results open on a summary for each question, in step order, with the response totals, device split and response ledger below. Each operator can ask for an email about every new completed response, per flow, on the flow's Results page: Immediately or Off. Publishing a flow turns it on for the publisher only; every other operator starts on Off. Flows from 0.1.0 that you do not republish start on Off for everyone. To turn the email on for one, open its Results page and choose Immediately under "Email me about completed responses", or republish the flow. The email names the business and the flow and links to the results, which need sign-in. It never carries an answer or a respondent's identity. It is sent from `MAIL_FROM`, which must be a `noreply@` or `no-reply@` address; sign-in keeps working with any other sender. Failures show on the Results page with Retry; an unknown outcome is never sent again unless you ask.

**Your brand.** Settings holds your business name, one supporting line, an accent colour and a PNG, JPEG or WebP logo, and the open flow shown at `/`. They appear on previews, public forms, embeds, the closed and completion pages and the email. Share offers a script embed that sizes itself to the form, and keeps the iframe code as an alternative. Six more question types: dropdown, yes/no, NPS, number, date and consent.

**Moving in and out.** The shared import kit accepts a Typeform definition JSON with an optional response CSV, or a Google Forms response CSV with an optional definition JSON retrieved by the read-only `forms.get` method. Google CSV-only imports create a flat editable draft; question-type suggestions are for review and are never applied automatically. Definition imports preserve only the supported fields and paths, and their reports name omissions, row errors and paths that need repair before publication. Review and explicitly accept the losses before commit. When a Google date value does not disambiguate its order, select the order; set the linked Sheet's IANA time zone and inspect the first and last timestamp previews. Google identity columns default to Skip. Explicitly mapping a normal email answer keeps it as answer data and creates no contacts, invitations or mail. Google Sheets scripts/settings, grids, file/time questions, quiz answer keys/scoring/validation/shuffle, images/videos and unsupported restart or looping paths do not move across. The import kit admits up to 8 MiB combined file bytes and 100,000 responses, subject to configured form and answer limits. Run the release-only qualification before every release; hosted capacity requires owner proof. Imported responses count in answers and the ledger but not in starts, completion rate or time. Undo removes an import. Use `node scripts/rer.mjs export --output exports/installation.rer` and explicitly confirmed `node scripts/rer.mjs import --input exports/installation.rer --yes` for complete local archive movement into an empty destination. Remote transfer is refused.

**Setting up.** Use `node scripts/rer.mjs install`, `node scripts/rer.mjs setup --owner-email EMAIL --owner-name NAME`, then `node scripts/rer.mjs dev`. Setup preserves existing owner, data and exact private settings, checks real one-use outbox sign-in, then stops its temporary app. Dev prints the health-gated app and Base outbox. Fresh owners finish the business name and time zone at `/setup`; other app routes send unfinished owners there. A completed workspace enters the app. `dev` opens signed in: it prints a `RER_OPEN` link for this computer that carries the checkout's private dev key, `--as operator` and `--login` choose another identity, and the local outbox answers only a request that holds the key. The installer and the sign-in confirmation page wear Pencil's own look.

**Product page and guide.** Every installation also serves Pencil's own product page at `/` by default (`/pencil` redirects there) and the owner guide at `/docs`, rendered at build time from the Markdown that `docs/site.json` lists (`docs/guide` and `docs/moving.md`); a broken link or anchor fails the build. Both set no cookies and load nothing from other sites. The product page opens on a note card whose answers show, by pointer or keyboard, the follow-up each one leads to. An explicit landing flow selection in Settings overrides the default product page and preserves the flow's canonical respondent experience, including closed and not-found states. SITE-001, SITE-002 and DOCS-001 are new clauses.

**Data and upgrades.** Export first and restore into a new empty database without replaying mail. Preserve applied migration bytes, credentials under their recorded versions and expiry, structure identities and graph links. RELEASE.json records the ordered migration inventory and buyer steps. Confirmed rer reset preserves source, exports and deployment receipts; a fresh setup after reset starts empty.

**Actions.** A new Actions page turns what results show into an owned action: title, rationale, owner, target metric with its baseline, review date, and a frozen copy of the results counts it rests on, with no response IDs or answers. The lifecycle (planned, in progress, ready for review, effective, ineffective, closed) is enforced on the server and every move and edit is recorded. Operators record a later observed value in the baseline's unit, see the difference, and mark the outcome effective or ineffective themselves; a passed review date shows Review due and nothing else happens. An optional webhook adapter (`TASK_PROVIDER=webhook`, `TASK_WEBHOOK_URL`, `TASK_API_KEY`) sends the exact confirmed JSON to a task system that creates or returns one task per idempotency key; delivery is pending, confirmed, unknown or failed with every attempt recorded, and retry reuses the key. Recommendations are written by people: the new ACT-008 clause makes a hand-written recommendation a source of an action until AI analysis exists. Migration `0026_actions.sql` adds these records additively.

Exactly 18 clauses remain deferred: ANLY-001–016, NOTIFY-001 and NOTIFY-003. Full-contract verification stays unsatisfied by design. Both importers were written from published documentation and checked with example files only; no real Google Forms or Typeform account export has been supplied or checked. Hosted capacity and live delivery are not claimed.

Audience now has editable contacts and bounded custom fields, reviewed CSV imports, saved segment rules and current counts. Invitations freeze evaluated policies and recipient snapshots and report actual outcomes; Audience erasure shows a count-only timed receipt. Migration `0025_audiences.sql` adds these records without rewriting earlier migrations.
