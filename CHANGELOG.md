# Release notes

## 0.2.0 - 2026-10-13

**Results and email.** Results open on a summary for each question, in step order, with the response totals, device split and response ledger below. Each operator can ask for an email about every new completed response, per flow, on the flow's Results page: Immediately or Off. Publishing a flow turns it on for the publisher only; every other operator starts on Off. Flows from 0.1.0 that you do not republish start on Off for everyone. To turn the email on for one, open its Results page and choose Immediately under "Email me about completed responses", or republish the flow. The email names the business and the flow and links to the results, which need sign-in. It never carries an answer or a respondent's identity. It is sent from `MAIL_FROM`, which must be a `noreply@` or `no-reply@` address; sign-in keeps working with any other sender. Failures show on the Results page with Retry; an unknown outcome is never sent again unless you ask.

**Your brand.** Settings holds your business name, one supporting line, an accent colour and a PNG, JPEG or WebP logo, and the open flow shown at `/`. They appear on previews, public forms, embeds, the closed and completion pages and the email. Share offers a script embed that sizes itself to the form, and keeps the iframe code as an alternative. Six more question types: dropdown, yes/no, NPS, number, date and consent.

**Moving in and out.** The shared import kit accepts a Typeform definition JSON with an optional response CSV, or a Google Forms response CSV with an optional definition JSON retrieved by the read-only `forms.get` method. Google CSV-only imports create a flat editable draft; question-type suggestions are for review and are never applied automatically. Definition imports preserve only the supported fields and paths, and their reports name omissions, row errors and paths that need repair before publication. Review and explicitly accept the losses before commit. When a Google date value does not disambiguate its order, select the order; set the linked Sheet's IANA time zone and inspect the first and last timestamp previews. Google identity columns default to Skip. Explicitly mapping a normal email answer keeps it as answer data and creates no contacts, invitations or mail. Google Sheets scripts/settings, grids, file/time questions, quiz answer keys/scoring/validation/shuffle, images/videos and unsupported restart or looping paths do not move across. The import kit admits up to 8 MiB combined file bytes and 100,000 responses, subject to configured form and answer limits. Run the release-only qualification before every release; hosted capacity requires owner proof. Imported responses count in answers and the ledger but not in starts, completion rate or time. Undo removes an import. Use `rer export --output exports/installation.rer` and explicitly confirmed `rer import --input exports/installation.rer --yes` for complete local archive movement into an empty destination. Remote transfer is refused.

**Setting up.** Use `rer install`, `rer setup --owner-email EMAIL --owner-name NAME`, then `rer dev`. Setup preserves existing owner, data and exact private settings, checks real one-use outbox sign-in, then stops its temporary app. Dev prints the health-gated app and Base outbox. Fresh owners finish the business name and time zone at `/setup`; other app routes send unfinished owners there. A completed workspace enters the app. `dev` opens signed in: it prints a `RER_OPEN` link for this computer that carries the checkout's private dev key, `--as operator` and `--login` choose another identity, and the local outbox answers only a request that holds the key. The installer and the sign-in confirmation page wear Pencil's own look.

**Product page and guide.** Every installation also serves Pencil's own product page at `/` by default (`/pencil` redirects there) and the owner guide at `/docs`, rendered at build time from the Markdown that `docs/site.json` lists (`docs/guide` and `docs/moving.md`); a broken link or anchor fails the build. Both set no cookies and load nothing from other sites. The product page opens on a note card whose answers show, by pointer or keyboard, the follow-up each one leads to. An explicit landing flow selection in Settings overrides the default product page and preserves the flow's canonical respondent experience, including closed and not-found states. SITE-001, SITE-002 and DOCS-001 are new clauses.

**Data and upgrades.** Export first and restore into a new empty database without replaying mail. Preserve applied migration bytes, credentials under their recorded versions and expiry, structure identities and graph links. RELEASE.json records the ordered migration inventory and buyer steps. Confirmed rer reset preserves source, exports and deployment receipts; a fresh setup after reset starts empty.

**Actions.** A new Actions page turns what results show into an owned action: title, rationale, owner, target metric with its baseline, review date, and a frozen copy of the results counts it rests on, with no response IDs or answers. The lifecycle (planned, in progress, ready for review, effective, ineffective, closed) is enforced on the server and every move and edit is recorded. Operators record a later observed value in the baseline's unit, see the difference, and mark the outcome effective or ineffective themselves; a passed review date shows Review due and nothing else happens. An optional webhook adapter (`TASK_PROVIDER=webhook`, `TASK_WEBHOOK_URL`, `TASK_API_KEY`) sends the exact confirmed JSON to a task system that creates or returns one task per idempotency key; delivery is pending, confirmed, unknown or failed with every attempt recorded, and retry reuses the key. Recommendations are written by people: the new ACT-008 clause makes a hand-written recommendation a source of an action until AI analysis exists. Migration `0026_actions.sql` adds these records additively.

**Analysis.** An optional analysis groups a published revision's completed text answers into ranked themes with one primary finding, through Base's ai client and the provider you configure (`AI_ENABLED`, `AI_MODEL`, and `AI_API_KEY` with optional `AI_BASE_URL`, or `MODELS_SERVICE` and `MODELS_KEY`). It is off until configured, and then only the selected answers and response IDs leave, in one structured request with `store: false`. Each run fixes the exact released responses it read; later responses mark it stale and never change it. Before anything shows, Pencil validates the answer's format, checks every cited response belongs to the run, checks every quote character for character against the stored answer, and recomputes every count and percentage; any mismatch fails the run with nothing shown. Themes below the disclosure threshold (5 by default) are withheld. The one recommendation, with confidence, expected impact and effort, becomes an owned action only when an operator chooses (the action records the analysis; nobody is contacted). Too little evidence completes as insufficient evidence; transient provider failures retry the same request at most three times within ten minutes; every call records its usage and cost (receipt, your rates, or not reported); a flow that closes with at least five completed responses can be analysed automatically. Erasing a response removes it from every analysis. Analysis was checked against a scripted local provider in the documented format, never against a live model. Migration `0033_analysis.sql` adds these records.

**Moving in, checked against Typeform's documentation.** The Typeform importer now reads the export's own `Start Date (UTC)` and `Submit Date (UTC)` headers, imports picture-choice and checkbox questions, suggests multiple-selection option columns by their labels, and keeps a question's paths when only a calculation was omitted. Erasing an imported response retires it from import custody with an append-only erasure journal; other respondents in the same file can still be continued or undone. `rer import --journal LATER` now refuses, whole, an archive made before a later erasure.

**Hosting.** `/health` reports the deployment that answered (commit, fingerprint and Worker version) beside the build, every built file is served when `rer deploy` runs the Worker first, and `deploy.json` binds `PENCIL_BUILD_ID`, the build label `/health` reports. Pencil runs the published `rer` 0.2.0 CLI, and every Base copy is at one Base revision; migrations 0027 to 0032 add Base's provider sign-in controls (off until an identity provider is linked), its import-kit undo fence and erasure journal, and Pencil's restore checkpoint. The import custody triggers are written in the form Cloudflare D1 parses, so `rer deploy` applies migration 0019 on a new database; 0034 gives an installation that applied the earlier text the same triggers. `rer-setup.json` declares the optional `oidc-provider@1` dependency; leaving `IDENTITY_PROVIDER` empty keeps email links.

Exactly 3 clauses remain deferred: ANLY-009 (builder assistance), NOTIFY-001 and NOTIFY-003. Full-contract verification stays unsatisfied by design. Both importers were written from published documentation and checked with example files only; no real Google Forms or Typeform account export has been supplied or checked. Hosted capacity and live delivery are not claimed.

Audience now has editable contacts and bounded custom fields, reviewed CSV imports, saved segment rules and current counts. Invitations freeze evaluated policies and recipient snapshots and report actual outcomes; Audience erasure shows a count-only timed receipt. Migration `0025_audiences.sql` adds these records without rewriting earlier migrations.
