# Release notes

## Unreleased

A checkout set up on one port now opens its app when `rer dev` or `rer demo` serves it on another.

## 0.7.0 - 2026-10-19

**Back up first.** Locally: stop dev, create the ignored exports folder (`mkdir -p exports`), export (`rer export --output exports/before-0.7.0.rer`), pull, then run `rer install`, `rer setup` and `rer dev`. Hosted: open **Backup** (`/app/backup`), download a backup, choose **Check backup** and then **Test restoration**, and only then run `rer deploy` on the same environment. Upgrading from 0.6.0 applies the additive migrations `0051_presentation_order.sql` and `0052_retention.sql`.

**Backup works on a Pencil installed by Run Edit Run.** Before 0.7.0, a Pencil installed by Run Edit Run (Managed) could not be backed up or moved. Both the **Backup** page and the recovery command (`node scripts/deployment-data-cli.mjs export`) refused with a migration-history error (`MIGRATION_MISMATCH`, or "The database migration history is ambiguous" on the Backup page). They did not recognise the migration ledger Run Edit Run keeps, `rer_migrations`. Both now check that ledger against Pencil's own migrations and export normally. A restore into another Run Edit Run installation checks the target's own ledger and never rewrites, drops or recreates it, so the target keeps its own record of when each migration ran. A ledger whose history differs from Pencil's is still refused, as is a database with two ledgers. Installations set up locally or with `rer deploy` are unchanged.

**Randomized order.** On a choice question you can shuffle the choices; **Other** and **None of the above** stay last. In a classic page or question group you can shuffle the questions. Each respondent keeps the order they first saw through preview, Back and resume. The order is stored with the response and included in CSV and JSON exports as presentation metadata, so you can check for order effects. Branching follows the form's logic, not the shuffled order.

**Retention schedules.** The owner can give a form a retention period. Released and quarantined responses and private Save and finish later saves older than that period are deleted under the normal response-erasure rules (aggregates recomputed, analyses marked redacted and stale). Deletion comes after at least seven days' notice in the app, including data that was already old when the schedule was turned on. A legal hold pauses all automatic deletion, including save expiry, and releasing it starts a fresh seven-day notice. Forms without a schedule keep everything, as before.

**What this release was checked against.** On 19 October 2026, Verify passed on the release source, including its installer and README jobs. A populated scratch database installed by Run Edit Run Platform's own migration runner was upgraded from the Pencil source Run Edit Run currently installs (43 migrations) to 0.7.0 (53 migrations). It was exported with the recovery command, restored into a second Platform-installed database whose ledger stayed byte-identical, and re-exported to a byte-identical archive. The hosted Backup page exported the same kind of database and passed **Check backup**. The populated 0.6.0 upgrade test applies 0051 and 0052 and keeps every row.

**Known issues.** You still cannot restore a hosted backup into a deployment that `rer deploy` has already claimed: the restore command refuses that target (`NONEMPTY_TARGET`) and writes nothing. An archive restores only into the Pencil version that made it. Back up before you upgrade, and keep your original deployment.

**Migrations.** `0051_presentation_order.sql` (each respondent session's presentation order; existing sessions get an empty order) and `0052_retention.sql` (per-form retention schedules and notices; every existing form stays without a schedule).

## 0.6.0 - 2026-10-19

**Back up first.** Locally: stop dev, create the ignored exports folder (`mkdir -p exports`), export (`rer export --output exports/before-0.6.0.rer`), pull, then run `rer install`, `rer setup` and `rer dev`. Hosted: open **Backup** (`/app/backup`), download a backup, choose **Check backup** and then **Test restoration**, and only then run `rer deploy` on the same environment. Upgrading from 0.5.0 applies migrations `0038_integration_connections.sql` to `0050_restricted_access.sql` in order. They add tables, columns and triggers; `0040_scores_contact_fields.sql` rebuilds the question and choice tables in place to allow the new question types and keeps every row and stable ID. A populated 0.5.0 install upgraded with every 0.5.0 row unchanged.

**Building forms.** New question types: CSAT, CES, emoji and thumbs ratings, phone, postal address, full name, URL and USD amount, with field-specific checks and normalized export columns. Choices can offer **Other** with a required write-in and an exclusive **None of the above**. Long choice lists up to 1,000 options can be pasted in bulk or filled from the built-in country and US state lists. A form can be one question per screen, classic pages with in-page conditions, or question groups. Prompts can recall earlier answers. Declared hidden link fields and calculations can drive answer paths, and rules can combine conditions with AND and OR. A flow can choose its thank-you screen or redirect to an approved HTTPS site after the response is saved. Forms can be saved as team templates.

**Sharing and collecting.** Named collectors give each channel its own link, close date and response limit, and every public collector has an SVG and PNG QR code. Kiosk mode restarts a form empty for the next person on a shared device and clears it after an idle time. A form can require a password, a verified email from an allowed list or domain, or a signed link from your own app. Respondents can choose **Save and finish later** and resume from an emailed link on any device for 30 days; nothing is kept unless they choose it. Respondent pages meet WCAG 2.2 AA across every question type and layout.

**Results.** Results show views, starts and submissions with start and completion rates; views are anonymous counts with no cookie or identifier. Trends over time, collector comparison and ledger search are new. Open-text answers can be coded by hand or by accepting exact-quote AI suggestions, then charted and crosstabbed. Each form has a submission inbox with statuses, assignees, tags and private notes. Honeypot and too-fast submissions are now kept for your review instead of dropped. They stay out of results, notifications and default exports, and an export can include them on request, each marked with its reason.

**Settings and sign-in.** AI and task connections are set up on their own pages in the app. Pencil pins rer 0.2.65. RER's **Open app** link opens `/signin` with the claimed owner's email filled in.

**What this release was checked against.** On 19 October 2026, the core loop ran on a fresh clone at 1440 and 390 px: setup, a branching form, preview showing which rule matched, publish, responses on two paths with path-only progress, no cookies and only same-origin requests, a respondent who started on revision 2 finishing it after revision 3 was published, results, a filtered CSV export, a Typeform import and `rer export`. A disposable Cloudflare deployment with SendGrid sent real sign-in, invitation (with its opt-out link) and new-response email to a real inbox. Direct, embedded and invited responses arrived, and the backup passed **Check backup** and **Test restoration** with the hosted-only answers in it.

**Not in this release.** These target clauses in CONTRACT.md are partial or missing: file uploads, payments, signatures, matrix grids, quizzes, multi-language forms, roles and SSO, integrations (Google Sheets, HubSpot, Slack, Zapier and others), shared report links and SMS. The homepage calls Pencil an alternative to Typeform, Google Forms and Jotform. That is true for the jobs the homepage shows, but not yet for every feature those products sell.

**Known issues.** You cannot yet restore a hosted backup into a new deployment. `rer deploy` claims the owner, so the restore command refuses the new database (`NONEMPTY_TARGET`) and writes nothing. Keep your original deployment, and use **Test restoration** or `scripts/deployment-data-restore-test.mjs` to prove an archive. A new Worker's cron can take up to about two hours to start on some Cloudflare accounts, which delays reminders and Daily digests until it does. Capacity limits are design targets, not measured hosted capacity. The Typeform importer has been checked against documented example files only.

**Migrations.** `0038_integration_connections.sql`, `0039_notification_timer.sql`, `0040_scores_contact_fields.sql`, `0041_collectors.sql`, `0042_submission_workflow.sql`, `0043_saved_responses.sql`, `0044_team_templates.sql`, `0045_traffic_metrics.sql`, `0046_exclusion_export_consistency.sql`, `0047_open_text_coding.sql`, `0048_condition_trees.sql`, `0049_hidden_fields.sql`, `0050_restricted_access.sql`.

## 0.5.0 - 2026-10-16

**Upgrading a local install.** Stop dev (`rer dev --stop`), create the ignored exports folder (`mkdir -p exports`), export (`rer export --output exports/before-upgrade.rer`), pull, then run `rer install`, `rer setup` and `rer dev`. Upgrading from 0.4.0 applies the additive migration `0037_import_progress.sql`, which adds the refreshed Base import kit's preparation checkpoints, stream sources and erasure progress; backups keep them. Hosted deployments apply it through `rer deploy`.

**Managed mail.** Managed hosting through RER sends Pencil email through the RER relay, without a separate mail provider account or API key. Free and Assisted installations retain the ordinary SendGrid or Resend choices; direct Cloudflare hosting still needs your own verified sender and provider key. Pencil pins rer 0.2.24, whose maintained mail adapter (since 0.2.23) fixes sign-in and invitation delivery from Cloudflare Workers. Relay redirects are refused, rate-limited notifications retry on schedule, and rejected notifications show the owner a plain explanation. RER's Open app link prefills the sign-in email from `login_hint`, using Base's email validation.

**Managed notifications.** On Managed hosting, response notifications and Daily digests send through the relay from RER's assigned verified sender (NOTIFY-004). With SendGrid or Resend they still need a plain `noreply@` or `no-reply@` sender.

**Sign-in and health.** A local Lobby's **Sign in** link carries `login_hint` for the one active owner on a loopback origin; a hosted Lobby is the same page for every visitor and never names its owner. On Managed hosting `/health` reports the built source commit, the release digest and the Worker version.

**Source checks.** Credential fixtures and examples are marked explicitly synthetic so hosted source checks accept them.

**Screenshot.** `.github/assets/release/pencil-0.5.0-results-1440.png` shows Results at 1440 px in local dev with sample responses.

## 0.4.0 - 2026-10-15

**Upgrading a local install.** Stop dev (`rer dev --stop`), export (`rer export --output exports/before-upgrade.rer`), pull, then run `rer install`, `rer setup` and `rer dev`. Upgrading from 0.3.0 applies migrations `0035_feedback.sql` and `0036_owner_signin.sql`. Both are additive. `rer dev` now applies pending migrations itself before it serves, and names them in its server log. If it cannot apply them, it refuses to start and tells you to run `rer setup`. Before this, a pulled source served by `rer dev` alone answered respondents with HTTP 500 and failed its scheduled job every minute until `rer setup` ran. Hosted deployments apply both migrations through `rer deploy`. See docs/guide/install.md.

**Daily digests.** Under **Email me about completed responses**, each operator can now choose **Daily** for a flow, alongside Immediately and Off. At the opening of the workspace's sending window, Pencil sends one digest of the interval's new released responses: counts only, never answers. Failed digests keep their day when retried. Switching away from Daily cancels pending digests, and restored digest history is never resent. Migration 0035 adds the digest records.

**Rewrite this question.** With an AI provider configured, **Rewrite this question** proposes a sharper, broader or contextual wording for a draft question. Only the saved question, the chosen style and your context are sent; answers never are. A proposal changes the draft only when you accept it, and Pencil refuses to accept it if the draft changed in the meantime. Accepting never changes choices or answer paths and never publishes. Every request is recorded with its usage.

**Analysis notifications.** The Analysis page lists your completed, insufficient-evidence and failed runs. You are notified of your own requests, and every operator who has not muted them is notified of automatic close-time runs.

**Add question keeps your answer paths.** Add question no longer reroutes the previous question to the new one. A new question leads to your completion screen, and nobody reaches it until an earlier question's rule or default next screen points to it. Publish refuses an unreachable question and names it. Owners used to 0.3.0's automatic routing should connect each added question.

**Signing in.** `rer signin --environment production` issues a private, single-use owner link for a hosted deployment, using its Cloudflare credentials and no email. Grants expire after 15 minutes and never travel in backups (migration 0036). `/signin` fills in its email field only from a `login_hint` parameter on a link you were given. It never shows an owner's address to a visitor: a build between 0.3.0 and this release did. First-run setup suggests your browser's time zone. Time-zone names are stored in their canonical IANA form, so `australia/brisbane` is kept as `Australia/Brisbane` and `US/Eastern` as `America/New_York`.

**Sending and forms.** Sending windows may cross midnight, for example 22:00 to 08:00. While analysis is on, the form's **Before you share** notice now says that contact, invitation and session identity is never sent, and that names or emails typed into a selected text answer are sent with that answer.

**Demo mode and local dev.** `rer demo` opens a disposable, signed-in **Pencil Demo** on the Aurora Coffee sample workspace (four weeks of responses ending today). Its state lives in `.rer/demo/` and is removed when it stops; the checkout's own `.wrangler/state` is untouched. Public reads run for real, while mail and other effects that would reach people or third parties return success without sending. `deploy-demo.json` and `.github/workflows/run-demo.yml` host the same demo at demo.run-pencil.com, one private container per visitor. Local dev now reads **Pencil Dev**, with no injected bar and no captured-mail outbox, and local mail is silently suppressed. The private `RER_OPEN` link signs you in, and so does **Continue as owner** at `/signin` once you have opened that link.

**Hosting and recovery.** Pencil pins `rer` 0.2.20. `rer deploy` claims the hosted owner and removes `SETUP_TOKEN` after the claim; leave it unset afterwards. A first deployment that succeeded no longer exits 1, and a request to the wrong host gets 503 naming `APP_ORIGIN`. `rer deploy --remove` is documented. `MAIL_PROVIDER` is no longer a variable in `wrangler.jsonc`: deploy.json declares it a deploy secret, and `rer setup` writes it to `.dev.vars`. Deployment selects SendGrid by default, or Resend when configured. The deployed backup and empty-target recovery command (`scripts/deployment-data-cli.mjs`) accepts the deployment kit's migration ledger and excludes Cloudflare's internal `_cf_KV` table. Restores carry no respondent session token hashes and no sign-in authorization. An explicit retry queued before an upgrade still sends once, with its original idempotency key. Setup explains that response notifications need a `noreply@` or `no-reply@` sender, and Results says plainly when notification email is off. A tagless copy of Pencil (a depth-1 checkout such as a Managed installation's repository) passes the release-upgrade gate, because it fetches the previous release tag from `rer-project.json`'s `sourceRepository`.

**Contract.** No clause is deferred. Draft rewrites (ANLY-009), analysis notifications (NOTIFY-001) and Daily digests (NOTIFY-003) are implemented and exercised by the feedback Worker cases. The importers were checked with documented-format synthetic files only, and the AI features only against scripted local providers. Large move-in review and preparation requests can still exceed the Workers request CPU limit (see docs/guide/moving-in.md). This release does not claim hosted capacity beyond the measured ceiling or live mail delivery.

## 0.3.0 - 2026-10-13

**Respondents are told when AI can read their answers.** While your deployment's AI provider is on, the **Before you share** note on every form adds that, if your business analyses feedback, the respondent's written answers may be sent to the AI service you chose, and that their name, email address and network address are never sent. With AI off the note reads as before. This is what RESP-005 asks of a configured external that may receive answers.

**Analysis.** An optional analysis groups a published revision's completed text answers into ranked themes with one primary finding, through Base's ai client and the provider you configure (`AI_ENABLED`, `AI_MODEL`, and `AI_API_KEY` with optional `AI_BASE_URL`, or `MODELS_SERVICE` and `MODELS_KEY`). These replace 0.2.0's unused `AI_PROVIDER`. It is off until configured, and then only the selected answers and response IDs leave, in one structured request with `store: false`. Each run fixes the exact released responses it read; later responses mark it stale and never change it. Before anything shows, Pencil validates the answer's format, checks every cited response belongs to the run, checks every quote character for character against the stored answer, and recomputes every count and percentage; any mismatch fails the run with nothing shown. Themes below the disclosure threshold (5 by default) are withheld. Too little evidence completes as insufficient evidence; transient provider failures retry the same request at most three times within ten minutes; every call records its usage and cost (receipt, your rates, or not reported). While a provider is configured, a flow that closes with at least five completed responses is analysed once automatically; turn that off or change the minimum under Analysis, Settings. Erasing a response removes it from every analysis. Analysis was checked against a scripted local provider in the documented format, never against a live model. Migration `0033_analysis.sql` adds these records.

**Actions from analysis.** An analysis's one recommendation, with confidence, expected impact and effort, becomes an owned action only when an operator chooses it; the action records the analysis it came from, and nobody is contacted. Hand-written recommendations work as before.

**Moving in, checked against Typeform's documentation.** The Typeform importer now reads the export's own `Start Date (UTC)` and `Submit Date (UTC)` headers, imports picture-choice and checkbox questions, suggests multiple-selection option columns by their labels, and keeps a question's paths when only a calculation was omitted. Erasing an imported response retires it from import custody with an append-only erasure journal; other respondents in the same file can still be continued or undone. `rer import --journal LATER` now refuses, whole, an archive made before a later erasure. The importer was checked with documented-format synthetic files; no real Typeform account export has been checked. On the hosted platform a review or preparation step can run out of Workers CPU at about 5,000 rows; docs/guide/moving-in.md has the measured ceiling.

**Invitations and reminders.** A pending delivery's retry count, due time and one-hour budget are checked again in the same atomic step that authorizes the send: exactly one hour after the first attempt is still allowed, a millisecond later is refused and the delivery shows as failed, and no budget runs more than six attempts, so a late queue wake-up can no longer send outside DIST-006. An operator's retry starts one new budget with the same idempotency key. A target or deadline that closes the current revision no longer stops invitations and sessions pinned to an older revision that is still open; closing a flow by hand, which stays available after an automatic close, and archiving still close every revision.

**Base and hosting.** Pencil continues to run the published `rer` 0.2.0 CLI (`rer install`, `rer setup`, `rer dev`), and every Base copy is at one Base revision. `/health` reports the deployment that answered (the commit, fingerprint and Worker version `rer deploy` recorded). `PENCIL_BUILD_ID` is retired: it is no longer required, bound or reported, so remove it from your environment. Every built file is served when `rer deploy` runs the Worker first. Migrations 0027 to 0032 add Base's provider sign-in controls (off until an identity provider is linked), its import-kit undo fence and erasure journal, and Pencil's restore checkpoint. `rer-setup.json` declares the optional `oidc-provider@1` dependency; leaving `IDENTITY_PROVIDER` empty keeps email links.

**Migration 0019 is rewritten, and 0034 converges it.** Cloudflare D1 ends a trigger at its first `END;`, so it refused the 39 import publication-fence triggers that 0.2.0's `0019_import_custody.sql` wrote as `SELECT CASE ... END;`. `rer deploy` stopped at 0019 on every new database, and 0.2.0 could not be hosted on Cloudflare. No later migration can fix that, because a deploy stops at 0019 before reaching it. So 0.3.0 states the same checks as `SELECT RAISE(...) WHERE EXISTS(...)` in 0019 itself. `0034_import_fence_triggers_d1.sql` drops and recreates those triggers, so a database that already applied 0.2.0's text (a local installation) ends with the same schema as a new one, with the same fence behaviour and no row changed. This is the one released migration whose bytes changed. `migrations/released-rewrites.json` names it with both exact hashes. The upgrade gate refuses any other change, and it checks that a populated 0.2.0 database upgraded to 0.3.0 has exactly a new database's schema.

Exactly 3 clauses remain deferred: ANLY-009 (builder assistance), NOTIFY-001 and NOTIFY-003, down from 18 in 0.2.0. Full-contract verification stays unsatisfied by design. Hosted capacity beyond the measured ceiling and live delivery are not claimed.

## 0.2.0

**Results and email.** Results open on a summary for each question, in step order, with the response totals, device split and response ledger below. Each operator can ask for an email about every new completed response, per flow, on the flow's Results page: Immediately or Off. Publishing a flow turns it on for the publisher only; every other operator starts on Off. Flows from 0.1.0 that you do not republish start on Off for everyone. To turn the email on for one, open its Results page and choose Immediately under "Email me about completed responses", or republish the flow. The email names the business and the flow and links to the results, which need sign-in. It never carries an answer or a respondent's identity. It is sent from `MAIL_FROM`, which must be a `noreply@` or `no-reply@` address; sign-in keeps working with any other sender. Failures show on the Results page with Retry; an unknown outcome is never sent again unless you ask.

**Your brand.** Settings holds your business name, one supporting line, an accent colour and a PNG, JPEG or WebP logo, and the open flow shown at `/`. They appear on previews, public forms, embeds, the closed and completion pages and the email. Share offers a script embed that sizes itself to the form, and keeps the iframe code as an alternative. Six more question types: dropdown, yes/no, NPS, number, date and consent.

**Moving in and out.** The shared import kit accepts a Typeform definition JSON with an optional response CSV, or a Google Forms response CSV with an optional definition JSON retrieved by the read-only `forms.get` method. Google CSV-only imports create a flat editable draft; question-type suggestions are for review and are never applied automatically. Definition imports preserve only the supported fields and paths, and their reports name omissions, row errors and paths that need repair before publication. Review and explicitly accept the losses before commit. When a Google date value does not disambiguate its order, select the order; set the linked Sheet's IANA time zone and inspect the first and last timestamp previews. Google identity columns default to Skip. Explicitly mapping a normal email answer keeps it as answer data and creates no contacts, invitations or mail. Google Sheets scripts/settings, grids, file/time questions, quiz answer keys/scoring/validation/shuffle, images/videos and unsupported restart or looping paths do not move across. The import kit admits up to 8 MiB combined file bytes and 100,000 responses, subject to configured form and answer limits. Run the release-only qualification before every release; hosted capacity requires owner proof. Imported responses count in answers and the ledger but not in starts, completion rate or time. Undo removes an import. Use `node scripts/rer.mjs export --output exports/installation.rer` and explicitly confirmed `node scripts/rer.mjs import --input exports/installation.rer --yes` for complete local archive movement into an empty destination. Remote transfer is refused.

**Setting up.** Use `node scripts/rer.mjs install`, `node scripts/rer.mjs setup --owner-email EMAIL --owner-name NAME`, then `node scripts/rer.mjs dev`. Setup preserves existing owner, data and exact private settings, checks real one-use outbox sign-in, then stops its temporary app. Dev prints the health-gated app and Base outbox. Fresh owners finish the business name and time zone at `/setup`; other app routes send unfinished owners there. A completed workspace enters the app. `dev` opens signed in: it prints a `RER_OPEN` link for this computer that carries the checkout's private dev key, `--as operator` and `--login` choose another identity, and the local outbox answers only a request that holds the key. The installer and the sign-in confirmation page wear Pencil's own look.

**Product page and guide.** Every installation also serves Pencil's own product page at `/` by default (`/pencil` redirects there) and the owner guide at `/docs`, rendered at build time from the Markdown that `docs/site.json` lists (`docs/guide` and `docs/moving.md`); a broken link or anchor fails the build. Both set no cookies and load nothing from other sites. The product page opens on a note card whose answers show, by pointer or keyboard, the follow-up each one leads to. An explicit landing flow selection in Settings overrides the default product page and preserves the flow's canonical respondent experience, including closed and not-found states. SITE-001, SITE-002 and DOCS-001 are new clauses.

**Data and upgrades.** Export first and restore into a new empty database without replaying mail. Preserve applied migration bytes, credentials under their recorded versions and expiry, structure identities and graph links. RELEASE.json records the ordered migration inventory and buyer steps. Confirmed rer reset preserves source, exports and deployment receipts; a fresh setup after reset starts empty.

**Actions.** A new Actions page turns what results show into an owned action: title, rationale, owner, target metric with its baseline, review date, and a frozen copy of the results counts it rests on, with no response IDs or answers. The lifecycle (planned, in progress, ready for review, effective, ineffective, closed) is enforced on the server and every move and edit is recorded. Operators record a later observed value in the baseline's unit, see the difference, and mark the outcome effective or ineffective themselves; a passed review date shows Review due and nothing else happens. An optional webhook adapter (`TASK_PROVIDER=webhook`, `TASK_WEBHOOK_URL`, `TASK_API_KEY`) sends the exact confirmed JSON to a task system that creates or returns one task per idempotency key; delivery is pending, confirmed, unknown or failed with every attempt recorded, and retry reuses the key. Recommendations are written by people: the new ACT-008 clause makes a hand-written recommendation a source of an action until AI analysis exists. Migration `0026_actions.sql` adds these records additively.

Exactly 18 clauses remain deferred: ANLY-001–016, NOTIFY-001 and NOTIFY-003. Full-contract verification stays unsatisfied by design. Both importers were written from published documentation and checked with example files only; no real Google Forms or Typeform account export has been supplied or checked. Hosted capacity and live delivery are not claimed.

Audience now has editable contacts and bounded custom fields, reviewed CSV imports, saved segment rules and current counts. Invitations freeze evaluated policies and recipient snapshots and report actual outcomes; Audience erasure shows a count-only timed receipt. Migration `0025_audiences.sql` adds these records without rewriting earlier migrations.
