# Pencil first-release candidate

The first release includes the implemented form, collection, distribution and reporting journey. The executable first-release profile defers exactly AUD, ANLY, ACT and NOTIFY (33 clauses). Deferred clauses remain TODOs, and `pnpm verify:contract:full` must remain red until they are implemented. Every baseline clause and every other product clause remains active. No hosted acceptance is inferred from local verification.

## Maintained source and authentication cutover

`edition.json` adopts maintained Base operator-auth and mail source from revision `712a4b43d8fc3f30b8d4c2f354c8a10e060bfc38`. Source mappings and `sources.lock.json` retain origin and resolved byte evidence; `src/base/provenance.json` also records copied file hashes. Pencil's adapters select equal owner authority, map Base identities to product ULIDs, preserve setup/last-operator protections, and keep dependencies server-side. SendGrid and Resend transports are maintained Base code; Pencil has no local production transport fork.

Migration `0010_base_operator_auth.sql` imports existing operators with their stable identities, records the one-time bootstrap ledger, and explicitly revokes legacy SHA-based links and `pencil_operator_session` sessions. All operators must sign in again. Migrations 0000–0009 retain their exact bytes. Old records remain available for recovery/export; no legacy credential path authenticates. Duplicate historical workspace emails retain their product data; only the deterministic earliest identity is admitted. An owner must resolve duplicate email ownership in a migration before granting the other identity access.

A fresh production installation has no operator until `POST /auth/bootstrap` succeeds with the configured one-time `SETUP_TOKEN`. The maintained Base transaction creates the owner and session exactly once. Subsequent requests return 409 even after deletion; remove the setup secret after acceptance. A migrated installation cannot bootstrap again. Existing operators request `/auth/magic-link`. Unknown addresses receive the same accepted response and create no operator. GET/HEAD `/auth/confirm` are read-only confirmation; only a same-origin POST consumes a link and creates a session. Production cookies are opaque Secure HttpOnly `__Host-operator_session`; loopback uses Base's explicit local cookie. Absolute expiry is 30 days. Origin, Host, fetch metadata, bounded strict input and Cloudflare client-IP guards are enforced. A missing edge IP fails closed. Uncertain mail revokes the sign-in link with no automatic retry.

The private `/app` documents, Hono APIs/docs and each private Start function require their own maintained session check. Public embeds receive the exact host allowlist plus `sandbox allow-scripts allow-forms` with no `allow-same-origin`; even an allowed host cannot read answers or cookies. Optional static credit defaults off.

## Durable mail and personal data

Invitations use a persisted launch, participant capability, delivery and attempt before Base mail egress. Recipient consent, current flow admission, deadlines/targets and prior completion are rechecked when claiming an attempt. Invitations initiated by an operator send immediately. Reminders use the stored IANA time zone and daily sending window. A minute Cron runs due work and privacy maintenance; launch/retry commands also run the dispatcher.

Rate-limit refusals retry at 1, 5, 15, 30 and 60 minutes from the first attempt, with the original correlation key. Permanent failure stays failed. Network/server uncertainty and abandoned in-flight attempts stay unknown, with no automatic resend. SendGrid correlation is not provider deduplication. An operator can explicitly retry an unknown outcome only after accepting duplicate risk. The UI displays status, reason and attempt count. Accepted SendGrid responses without message IDs retain null; no receipt is fabricated.

Erasure removes personal contact/answer/local-mail material and revokes invitation credentials while preserving anonymous audit and delivery facts. Full export/import/export includes every current table, Base auth/mapping/bootstrap/rate state, all distribution data, old auth history, exact text/int64, and the exact migration ledger. Restore validates compiled schema and ledger and creates an exclusive new database; it never overwrites existing data or sends mail. Recovery is an export before migration and a tested restore to a new database before changing bindings. Archives contain credentials and personal data and are created mode 0600.

The contract gate executes the complete desktop and mobile native suites in separate freshly migrated runtimes. Hosted install, inbox receipt, health, CI outcome and teardown receipts belong to the integrating release owner.
