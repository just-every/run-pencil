# Pencil 0.3.0 release scope

Pencil includes the form, collection, distribution and reporting journey, response notifications, saved business identity, six additional question types, embeds, reviewed Typeform imports and Google Forms CSV-first imports with an optional `forms.get` definition. A CSV without a definition creates a flat editable draft; it cannot reconstruct unseen choices or branching. Google Forms definitions support only a bounded set of question types and paths, with unsupported details named for review and affected paths to repair before publication. Owned actions (ACT-001 to ACT-008) are included: operators turn results into actions with frozen evidence counts, measure them and set the verdict themselves, and may send a confirmed task through the optional webhook adapter. Grounded analysis (ANLY-001 to ANLY-008 and ANLY-010 to ANLY-016) is included on Base's ai client: off until a provider is configured, it reads only the selected text answers of released responses, validates every theme, count and quote against its fixed evidence before anything shows, withholds themes below the disclosure threshold, and proposes one recommendation an operator can turn into an action they own. It was checked against a scripted local provider only, never a live model. The first-release profile retains exactly 3 deferred clauses: ANLY-009 (builder assistance), NOTIFY-001 and NOTIFY-003. Their TODOs and the unsatisfied `pnpm verify:contract:full` gate remain. Every other product and baseline obligation stays active.

## Run and qualify

Use the pinned tools and rer recipe in README.md: install, setup with the owner's email, dev, sign in through the printed Base outbox, then finish business name and time zone at `/setup`. Established workspaces retain their completed setup and data. `rer verify` runs types, functional unit and Worker checks, the complete portable onboarding suite, real local command and no-JavaScript setup journeys, archive round trips/refusals, populated upgrades, manifest, boundaries, build and native desktop/mobile contract journeys.

Run `pnpm run verify:release` before every release for capacity, maximum-size native memory, browser heap and load. The maintained `pnpm run release -- --repo . --ref HEAD --project just-every/pencil --repository https://github.com/just-every/run-pencil --onto https://github.com/just-every/run-pencil#main --tag vVERSION --dry-run --output ../pencil-release` requires both verification commands and a complete scan of the public child and its public history with zero findings and reviews. Its release receipt records the actual source head, command results and scan; a command description is not a successful release receipt.

## Upgrade and recovery

Export before applying the ordered committed migrations and verify restoration into a new empty database before switching the running binding. The released 0.2.0 predecessor contains migrations 0000–0026; the intended transition adds 0027–0034 in order. Hosted upgrades through rer 0.2.1 are blocked as described below. Migration 0025 adds Audience. Migrations 0027–0033 add Base provider controls, import undo and erasure records, a restore checkpoint, and grounded analysis. Migration 0034 recreates the import publication-fence triggers in the form Cloudflare D1 parses.

`0019_import_custody.sql` is the one released migration whose bytes 0.3.0 rewrites. `migrations/released-rewrites.json` records both hashes; the name-based Workers D1 test retains the old migration entry and reaches 0034, which converges its trigger schema with a fresh install without changing rows or fence behavior. This is not the deployed kit’s hash-ledger path. The upgrade gate refuses every other released-migration rewrite and checks the populated 0.2.0 upgrade in Workers D1. `pnpm verify:migrations` requires the reachable 0.2.0 predecessor and checks retained values, graph relationships, duplicate command handling, foreign keys, replay and real notification dispatcher suppression after opt-in. Native sessions and links retain their recorded versions and expiry; credentials revoked by migration 0010 stay revoked.

The installed rer 0.2.1 deploy kit rejects the released 0019 hash with `changed-or-uncertain-migration-history`, makes zero upgrade writes, and never reaches 0034. It has no supported input for Pencil’s released-rewrite declaration. Hosted 0.2.0 upgrades require a maintained Base contract that authenticates the exact released migration bytes, preserves their actual ledger history and safely applies the additive convergence migration. Do not alter ledger hashes, weaken the refusal or switch controllers to bypass it. Retain the prior source and database and use only a supported matching-version backup path until that contract is available. This source’s deployed recovery CLI also validates migration hashes; it does not establish export compatibility with the old 0019 history. Fresh deployment and local name-based upgrade checks do not fulfil this hosted upgrade obligation.

Use rer export/import through the local recovery commands in [LOCAL-DATA-RECOVERY.md](LOCAL-DATA-RECOVERY.md); that reference also describes the separate maintained command for deployed D1 recovery. Archives contain personal data, never sessions, sign-in links or credentials, and are created with mode 0600 in a private directory or the ignored `exports` directory. Plaintext participant capabilities and captured mail are excluded. Historical notification eligibility is disabled, while durable delivery outcomes remain. Never overwrite a live database or replay mail to demonstrate recovery. The public rer commands continue to refuse remote transfer.

## Mail, privacy and imports

Each operator chooses Immediately or Off per flow. Publishing selects Immediately for its publisher only when their preference is unset; other operators default Off. A released new response creates at most one delivery per opted-in operator. Messages name the business, flow and submission time and link to authenticated results without answers or respondent identity.

Delivery attempts are durable before egress. Transient failures use bounded retries with the same idempotency key. Permanent failures stay visible; uncertain outcomes remain unknown without automatic resend. Explicit retry acknowledges duplicate risk. Configured no-reply messages are auto-generated, and incoming mail cannot create a response or notification. Daily digest and analysis notifications remain deferred.

Imports require review of supported fields, mapping changes, omissions and row errors before commit. Google date order is inferred only when a value disambiguates it; otherwise the operator selects the order. Every Google CSV import uses the source Sheet's IANA time zone and checks the first and last timestamp preview. Google identity columns are skipped by default; explicitly mapped ordinary email answers remain answer data and create no contacts, invitations or mail. Historical answers retain timestamps and their immutable revision. Hidden values and network metadata are discarded before durable planning; original file bytes are not retained. The maintained import kit provides replay identity, bounded resume and undo while protecting later native edits. Google Sheets scripts/settings, quiz keys and scoring, validation and shuffling, media, file/time questions and grids are not moved. Both importers have been checked with examples based on published documentation; neither has been checked against a real account export.

Public embeds retain the exact host allowlist and an opaque sandbox without same-origin access. Business logos are intentionally public installation-hosted D1 images under BRAND-001; private upload/download guarantees remain unchanged. Optional static credit defaults off.
