# Hosting Pencil

Use Node 22.20.0 and pnpm 10.12.4. Install with `rer install`, qualify the exact source with `rer verify` and run `pnpm run verify:release` before release. `pnpm run deploy -- --dry-run` validates the real Worker/assets/migrations and owner declaration with zero provider requests.

Actual `pnpm run deploy -- --environment production` requires the intended Cloudflare account/API token and production SESSION_SECRET, SETUP_TOKEN, SEED_ADMIN_EMAIL, MAIL_FROM and MAIL_API_KEY. Supply them privately through the authorized deployment environment, never argv or output. `PENCIL_MAIL_PROVIDER` selects `sendgrid` (the default) or `resend`; the earlier `MAIL_PROVIDER` environment setting is accepted when it agrees. The deploy adapter passes this through the published kit as the Worker’s `MAIL_PROVIDER` binding. Choose it and the matching `MAIL_API_KEY` before the first deploy: subsequent deployments inherit existing secrets. deploy.json selects production mail, derived resource identities, scheduled maintenance, ordered D1 migrations and public origin; local capture and sample data are disabled. A healthy Worker does not prove real mail delivery or hosted capacity.

The owner uses native Base sign-in and finishes `/setup`. Preserve owner data and opaque existing provider secrets. Export before upgrades, verify restore into an empty database and retain a compatible deployment until owner acceptance. Never replay mail in recovery. Hosted managed admission requires owner proof; a private push or dry run installs nothing. Tags, public publication and site listing are separate owner actions after full release verification and a zero-finding scan.

After owner bootstrap, retain the deployed SETUP_TOKEN. An initialized installation refuses another owner claim. The token may be unset in the calling environment because repeat deployments inherit it. Do not mutate Worker secrets in the dashboard: rer 0.2.1 treats that new Worker version as `owned-resource-replaced`. Keep and privately back up `.rer/deploy/<environment>.json`; do not edit it to bypass the refusal. A Worker already changed outside rer requires the deploy kit’s supported ownership recovery.

This hosting path requires Workers Paid and uses its default 30,000 ms request CPU budget; Workers Free’s 10 ms limit is a different service tier. Pencil being free software does not select a free provider plan. rer 0.2.1 rejects `limits.cpu_ms` in the owner declaration and emits no CPU limit in upload metadata, so an explicit per-Worker budget requires a future supported deploy-kit contract. Consult [Cloudflare’s limits](https://developers.cloudflare.com/workers/platform/limits/).
